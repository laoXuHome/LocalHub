## 一、需求逐项实现情况

| 需求 | 实现 | 证据 |
| --- | --- | --- |
| 单管理员账户，不提供注册/多管理员 | `admin_users` 表 + `CreateAdmin` 内部强制 `COUNT(*)==0` 才能创建；无任何注册路由 | `internal/auth/store.go`、`TestSingleAdminConstraint` |
| 首次启动完成管理员初始化 | 管理员表为空且设置了 `LOCALHUB_ADMIN_PASSWORD` 时，启动阶段自动创建；已存在管理员时忽略该变量、不覆盖 | `approle.bootstrapAdmin`、`TestNeedsSetupWhenNoAdmin`、CI compose 冒烟 |
| 管理员登录 | `POST /api/auth/login`（JSON），成功后下发 HttpOnly 会话 Cookie | `TestLoginLogoutFlow`、CI `login HTTP 200` |
| 退出登录 | `POST /api/auth/logout`（管理员），服务端吊销会话并清 Cookie | `TestLoginLogoutFlow`、CI `logout 200 → whoami 401` |
| 密码修改 | `POST /api/auth/password`：校验旧口令、新口令策略、禁止与原密码相同，改密后吊销其他设备会话 | `TestChangePasswordRevokesOthers` |
| 访客可访问公开内容 | `/`、`/health`、`/api/auth/status` 公开；静态页对访客可读 | `TestPublicRoutesAccessibleToVisitor` |
| 访客不能访问管理员功能（后端执行） | `/api/auth/logout`、`/api/auth/password`、`/api/admin/*` 统一经 `requireAdmin` 中间件校验服务端会话，未登录返回 401 | `TestAdminAPIRejectsVisitor`、CI `guest whoami 401` |
| 后端登录鉴权与安全会话 | 服务端会话表（令牌 SHA-256 存库，明文只在 Cookie）；HttpOnly + SameSite=Lax + Path=/；可选 Secure；默认 12h 到期；每小时清理过期会话 | `internal/auth/session.go`、`TestSessionLifecycle`、`TestExpiredSessionRejected` |
| 登录状态有效期与退出失效 | `expires_at` 校验 + `revoked_at` 吊销；过期/吊销一律 401 | 同上 |
| 密码安全哈希、不得明文 | bcrypt cost 12（随机盐）；库中只有 `$2...` 哈希；日志不记录口令 | `TestHashAndCompare`、`TestPasswordNotStoredInPlaintext` |
| 登录失败次数限制/暴力破解防护 | 按 IP+用户名统计窗口内失败次数，达到阈值后锁定并在锁定期间拒绝（含正确口令）；返回 429 + `Retry-After`；成功登录清除失败记录 | `TestLoginLockout`、CI `wrong password 401` |
| 权限基础预留（书签） | 统一 `requireAdmin` + 请求上下文注入会话；后续业务接口可直接复用同一守卫 | `approle.requireAdmin` |
| 访客/管理员边界明确 | 见下表 | 路由与测试 |

### 公开 / 管理员边界

| 路径 | 方法 | 访客 | 管理员 |
| --- | --- | --- | --- |
| `/`、静态资源、`/health`、`/api/auth/status` | GET | 200 | 200 |
| `/api/auth/login` | POST | 200/401/429 | — |
| `/api/auth/logout` | POST | 401 | 200 |
| `/api/auth/password` | POST | 401 | 200/400/403 |
| `/api/admin/*` | GET | 401 | 200 |

### 安全措施

1. 口令：bcrypt cost 12；策略 12–72 字节（bcrypt 上限）。
2. 令牌：32 字节随机，库中存 SHA-256，Cookie 为 HttpOnly + SameSite=Lax，可选 `Secure`。
3. 用户不存在时也执行一次 bcrypt 比较，避免时间差枚举账户。
4. 写操作校验 `Origin` 与 `Host` 一致（缓解 CSRF），配合 SameSite=Lax。
5. 限速：默认 15 分钟内 5 次失败 → 锁定 15 分钟；锁定期间不延长锁定（不记录新的失败）。
6. 改密后吊销其他会话；退出立即吊销当前会话。
7. 日志只记录用户名/IP/结果码，不记录口令与令牌。

## 二、数据结构（迁移 0002，schema v2）

- `admin_users`：单管理员，`password_hash` 仅存 bcrypt。
- `sessions`：`token_hash` 唯一、`expires_at`、`revoked_at`、`last_seen_at`、`ip`、`user_agent`。
- `login_attempts`：`ip`、`username`、`success`、`attempted_at`，用于窗口统计。

## 五、未完成事项及原因

1. 未提供口令找回/邮件重置：单管理员、无外部依赖，属于未批准需求。
2. 未提供 2FA/TOTP：未在任务书范围内。
3. CSRF 采用 Origin 校验 + SameSite=Lax，未引入双提交 token：当前单页 + JSON API 形态下足够；若后续开放跨站集成需升级。
4. 未提供登录审计查询界面（记录已落库）：属 P3/系统设置范围。
5. 会话仅存储于本机 SQLite，不支持多实例共享：符合 P0 单容器约束。
6. 访客可读内容目前仅首页与 `/api/auth/status`：P2 书签公开范围尚未定义，未提前实现。
7. 未在真实 NAS 上做浏览器端手工验收：环境无 Docker，容器级验证在 GitHub runner 完成。
