## 2. 架构与安全边界

```text
LocalHub 容器
  └─ HTTP GET /version
       └─ docker-socket-proxy:2375（内部网络 docker-proxy）
            └─ /var/run/docker.sock（只读挂载）
                 └─ 宿主机 Docker Engine
```

关键约束：

1. `localhub` 服务只挂载数据目录，不挂载 `/var/run/docker.sock`。
2. 只有 `docker-socket-proxy` 服务只读挂载 Socket。
3. Proxy 只 `expose 2375`，不发布宿主机端口；只加入 `docker-proxy` 内部网络。
4. Proxy 以非 root 的 `65534:65534` 运行，通过 `group_add` 获得 Socket 组权限；`read_only: true`、`no-new-privileges:true`。
5. `SP_ALLOWFROM` 默认只允许 Compose 中的 `localhub` 服务。
6. 未配置 POST/PUT/PATCH/DELETE allowlist，写方法默认拒绝。

Socket 引用边界检查见 `docs/p5.1/socket-boundary.txt`：除 Proxy 的只读挂载外，LocalHub 服务无 Socket 挂载；Go 代码无 `unix://` Docker 客户端，配置校验明确拒绝 `unix://`。

## 3. 后端实现

### 3.1 只读客户端

新增 `internal/dockerclient/dockerclient.go`：

- 只实现 `GET /version`，不使用 Docker SDK。
- 未配置地址返回 `not_connected`。
- 地址只接受 `http://`、`https://`、`tcp://`；`tcp://` 归一化为 `http://`。
- 拒绝 `unix://`、URL 用户信息、路径、查询参数和片段。
- 不跟随重定向；响应体限制 1 MiB；默认超时 3s。
- 401/403 映射 `permission_denied`；502/503/504 映射 `service_unavailable`；网络拒绝/超时映射 `connection_failed`；200 但 JSON 缺少 `ApiVersion`/`Version` 映射 `unknown`。
- 返回结构只有 `status`、`api_version`、`checked_at`、`message`、`read_only`，不含 URL、Socket 路径、响应体或内部错误文本。

### 3.2 配置

`internal/config/config.go` 新增：

- `LOCALHUB_DOCKER_API_URL`
- `LOCALHUB_DOCKER_TIMEOUT`（500ms–30s）

空地址不阻止启动。非法地址在启动期报配置错误；连接不上、权限不足、服务不可用均不阻止启动。

### 3.3 路由与鉴权

- 新增 `GET /api/admin/docker/status`，由现有 `requireAdmin` 保护。
- 状态接口始终以 HTTP 200 返回状态对象；上游失败不抛 5xx。
- 请求超时为客户端超时 + 1s。
- 访客返回 401；响应不泄露 fixture URL、`127.0.0.1`、Socket 路径、`error` 或上游 `forbidden` 文本。
- Docker 客户端初始化失败只记录警告，不导致 `Run` 退出。

## 5. 部署配置

Compose 新增 `docker-socket-proxy` 服务：

```yaml
image: ${LOCALHUB_DOCKER_PROXY_IMAGE:-wollomatic/socket-proxy:1.14.0}
volumes:
  - /var/run/docker.sock:/var/run/docker.sock:ro
expose:
  - "2375"
group_add:
  - "${LOCALHUB_DOCKER_GID:-999}"
read_only: true
security_opt:
  - no-new-privileges:true
```

LocalHub：

```yaml
environment:
  - LOCALHUB_DOCKER_API_URL=${LOCALHUB_DOCKER_API_URL:-http://docker-socket-proxy:2375}
  - LOCALHUB_DOCKER_TIMEOUT=${LOCALHUB_DOCKER_TIMEOUT:-3s}
volumes:
  - ${LOCALHUB_DATA_DIR:-./localhub-data}:/data
networks:
  - default
  - docker-proxy
```

`LOCALHUB_DOCKER_GID` 必须按部署机实际 Socket 组号设置：

```sh
stat -c '%g' /var/run/docker.sock
```

完整说明、allowlist、排障步骤见 `docs/p5.1-docker-proxy.md`。

## 7. 连接状态验证

| 状态 | 触发方式 | 结果 | 证据 |
|---|---|---|---|
| `connected` | 本地真实 Proxy + Docker Engine | `api_version=1.52` | `status-connected-final.json`；桌面/移动截图 |
| `not_connected` | 不配置 URL | “尚未配置 Docker 连接” | `status-none.json`；`desktop-not-connected.png` |
| `connection_failed` | 指向无监听端口；CI 停止 Proxy | “无法连接 Docker 服务” | `status-fail.json`；`docs/p5.1/ci/p51-outage.log` |
| `permission_denied` | 真实 Proxy ACL 拒绝来源 | “Docker 连接权限不足” | `status-permission-denied.json`；`permission-denied-body.txt` |
| `service_unavailable` | 停止真实 dockerd，保留 Proxy | “Docker 服务暂时不可用” | `status-service-unavailable.json`；`docker-down-proxy-response.txt`（502） |
| `unknown` | 200 但返回非 Docker JSON | “Docker 状态未知” | `status-unknown-simulated.json`（模拟响应） |

**真实与模拟区分：**

- `connected`、`connection_failed`、`permission_denied`、`service_unavailable`、`not_connected` 均由真实 HTTP 请求触发。
- `unknown` 的 200 响应来自本地临时 Python fixture，是**模拟 Docker 响应**，仅用于验证客户端对非法/非 Docker JSON 的映射，不代表真实 Docker 环境。
- 本地沙箱无法运行容器（mount/namespace 受限），但 CI 已用真实 Proxy 容器和真实 Docker Engine 完成 V-02 与 Compose 验证；本地结论只声称“真实 Proxy 进程 + 真实 Docker Engine API”，不声称“本地容器化 Compose 已验证”。
