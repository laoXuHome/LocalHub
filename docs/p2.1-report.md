### 1.2 权限落地方式

任务书要求「四种权限：公开 / 登录后可用 / 仅个人可见 / 禁用」。实现为 `visibility`（三种可写入值）+ `enabled`，**「禁用」= `enabled=false`**，对外由 `effective_visibility` 统一返回 `disabled`，避免同一语义两套字段：

| 场景 | 访客 | 管理员 |
| --- | --- | --- |
| 公开（public，启用） | 可见、可读 | 可见、可读 |
| 登录后可用（authenticated，启用） | 不可见（404） | 可见、可读 |
| 仅个人可见（private，启用） | 不可见（404） | 可见、可读 |
| 禁用（enabled=false） | 不可见（404） | 公开列表不可见；管理列表可见并可重新启用 |

不可见统一返回 `404 not_found`，不泄露书签是否存在。`visibility` 写入 `disabled` 会被拒绝（400），禁用只能通过 `enabled` 表达。

### 1.3 接口清单

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/bookmarks` | 公开 | 按权限过滤的列表，返回 `items/total/role` |
| GET | `/api/bookmarks/{id}` | 公开（按权限过滤） | 单条读取，越权/不存在均 404 |
| GET | `/api/admin/bookmarks` | 管理员 | 管理列表，含禁用项 |
| GET | `/api/admin/bookmarks/{id}` | 管理员 | 管理单条读取 |
| POST | `/api/admin/bookmarks` | 管理员 | 新增，返回 201 |
| PUT | `/api/admin/bookmarks/{id}` | 管理员 | 编辑，未提供字段保持不变 |
| DELETE | `/api/admin/bookmarks/{id}` | 管理员 | 删除，目标必须存在，重复删除 404 |
| POST | `/api/admin/bookmarks/batch-delete` | 管理员 | 批量删除，返回 `deleted/missing`，上限 200 |
| POST | `/api/admin/bookmarks/order` | 管理员 | 按 ID 序列 0 基重排，事务执行 |

管理接口全部包在 `requireAdmin` 中间件内，鉴权在服务端执行，与前端是否显示按钮无关。路由改用 Go 1.23 方法级模式（`GET /api/bookmarks/{id}` 等），原先的 `/api/admin/` 通配已收窄为 `GET /api/admin/whoami`。

### 1.4 输入校验与目标校验

- URL 只允许 `http/https`，必须带 host，不接受空白字符；LAN、WAN 至少提供一个。
- 名称非空且 ≤64 字节；描述 ≤200；icon_value ≤512；docker_container ≤128 且禁换行。
- `icon_type=url` 时 icon_value 必须是 `http/https` URL；`icon_type=none` 不允许带值。
- `open_mode` 仅 `new_tab/self`（旧写法 `current_tab` 归一化为 `self`）；`sort_order` 不得为负。
- 批量删除/排序的 ID 必须为正整数、去重后不超过 200；排序要求每个 ID 都存在，且不允许重复。
- 编辑、删除先按 ID 精确读取，不存在返回 404，不做静默忽略。

### 1.5 排序行为

- 新增时未指定 `sort_order`（0）则追加到 `MAX(sort_order)+1`。
- 排序接口在一个事务内把给定 ID 依次写成 0..n-1，失败整体回滚。
