LocalHub P2.2 施工任务书｜书签图标管理与 Favicon 安全抓取

P2.2 Implementation Task Order

项目阶段： P2 书签核心（Bookmarks Core）
批次： P2.2

一、施工目标

在 P2.1 已完成的书签数据模型和基础管理接口之上，建立完整的书签图标管理能力。

支持书签图标信息保存、读取、更新、删除，以及通过书签 URL 安全获取 Favicon。

图标资源必须保存在 LocalHub 本地数据目录，不依赖第三方云存储，确保服务重启后仍然可用。

二、本批实施范围

1. 图标管理

实现以下能力：

* 保存书签图标信息。
* 读取书签当前图标。
* 更新或替换书签图标。
* 删除书签图标。
* 支持图标与书签正确关联。
* 书签删除后，正确处理关联图标。
* 图标文件使用稳定的本地存储方式。
* 图标文件不得存储在容器临时目录。

2. Favicon 自动获取

实现根据书签 URL 自动获取网站图标的能力。

要求：

* 支持常见网站 Favicon 获取方式。
* 获取失败时不得影响书签创建、编辑及正常访问。
* 获取失败应保留默认图标或无图标状态。
* 支持重新获取。
* 不得因为获取图标而阻塞主要书签管理操作。
* 图标获取结果必须持久化到本地。

3. SSRF 安全防护

Favicon 获取必须具备完整的 SSRF 防护。

必须防止：

* 访问 localhost 和回环地址。
* 访问内网、局域网及私有 IP。
* 访问链路本地地址。
* 访问云服务元数据地址。
* 通过 DNS 解析或重定向绕过地址限制。
* 通过非 HTTP/HTTPS 协议访问本地资源。
* 通过异常响应、超大文件或恶意内容消耗系统资源。

不得将用户提供的 URL 直接作为可信目标访问。

4. 文件与数据安全

* 图标文件必须限制大小。
* 必须验证文件格式和实际内容。
* 文件名不得直接使用用户输入。
* 不得允许路径穿越。
* 图标文件损坏或不存在时，系统应能正常运行。
* 图标存储应遵守 P0 数据目录约束。
* 不得破坏 P1.1 账户数据和 P2.1 书签数据。

3. 书签删除后关联图标处理正确。
4. Favicon 获取成功、失败及重新获取流程正常。
5. 获取失败不影响书签 CRUD。
6. SSRF 防护覆盖回环地址、私有地址、DNS 解析、重定向及元数据地址。
7. 文件大小、格式、路径及恶意内容校验有效。
8. 图标文件持久化，容器重启后仍可读取。
9. 图标文件异常不影响系统启动及其他书签。
10. P0、P1.1、P2.1 原有测试全部保留并通过。

## 附录 B：P2.3 原始施工任务书（原文照录）

LocalHub P2.3 施工任务书｜书签导入与导出

P2.3 Implementation Task Order

一、施工目标

在已验收的 P2.1 书签数据基础和 P2.2 图标管理能力上，实现完整的书签导入与导出能力。

支持 Chrome、Edge、Sun-Panel、LocalHub JSON 导入，以及 LocalHub JSON、标准 HTML 导出。

本批只建设后端导入导出能力及必要的数据处理接口，不开发前端管理页面。

二、实施范围

1. 导入格式

必须支持以下来源：

* Chrome 标准书签 HTML。
* Edge 标准书签 HTML。
* Sun-Panel 书签数据。
* LocalHub JSON。

导入时应尽可能保留：

* 书签名称。
* URL。
* LAN/WAN URL（来源支持时）。
* 描述。
* 图标信息（来源支持时）。
* 打开方式（来源支持时）。
* 权限信息（LocalHub JSON）。
* 原始文件中的文件夹层级信息（来源支持时）。

不得因为来源格式不支持某些字段而导致整批导入失败。对无法映射或不支持的字段，应明确给出警告。

2. 导入预览与确认

导入必须采用预览、确认、执行的流程。

预览阶段至少提供：

* 文件格式识别结果。
* 可导入书签数量。
* 无效记录数量。
* 重复记录数量。
* 字段映射及不支持字段警告。
* 可选择的导入范围。
* 每条异常记录的失败原因。

用户确认后才能真正写入数据库。

不得在预览阶段修改现有书签数据。

3. 重复检测与冲突处理

必须实现重复书签识别。

处理规则：

* 默认不覆盖已有书签。
* 支持跳过重复项。
* 支持用户手动决定重复项的处理方式。
* 不得未经确认覆盖已有书签。
* 重复判断不能仅依赖书签名称，应结合 URL 等信息识别。
* 导入结果必须明确区分新增、跳过、失败数量，并提供具体原因。

导入失败不得损坏已有书签。

4. LocalHub JSON 导出

JSON 导出用于完整迁移，尽可能保留 LocalHub 书签数据。

必须包含：

* 书签名称。
* LAN URL。
* WAN URL。
* 图标及图标信息。
* 描述。
* 权限设置。
* 启用状态。
* 打开方式。
* 排序信息。
* 其他已存在且属于书签的数据字段。

图标必须能够随 JSON 迁移，不能只导出原设备上的本地文件路径。

必须包含格式版本信息，为后续兼容升级预留基础。

支持：

* 导出全部书签。
* 导出用户选定的书签。
* 按权限过滤导出内容。

导出操作不得修改源数据库中的任何书签。

5. 标准 HTML 导出

导出符合浏览器兼容要求的书签 HTML。

必须支持：

* 书签名称。
* URL。
* 浏览器兼容的文件格式。
* 可表达的文件夹层级结构。

不得为了实现 HTML 导入导出而引入新的书签分类或标签体系。

6. 权限与数据安全

* 导入、导出管理操作必须经过管理员鉴权。
* 访客不得执行导入、导出管理操作。
* 不得通过导入文件绕过已有权限规则。
* LocalHub JSON 中的权限信息必须经过合法性校验。
* 文件内容必须进行格式与数据合法性检查。
* 非法记录应隔离处理，不得污染已有数据。
* 图标导入必须复用 P2.2 已有的图标安全校验及本地存储能力。
* 不得将用户提供的文件名直接用于服务器文件路径。
