## 1. 交付摘要

P4.4 新增一个纯地址选择层，书签最终打开哪个地址由同一函数决定：

- 手动 LAN：始终选 LAN 地址。
- 手动 WAN：始终选 WAN 地址。
- AUTO + LAN：选 LAN。
- AUTO + WAN：选 WAN。
- AUTO + UNKNOWN、判断中、无结果：返回 `default`，沿用 P4.4 之前的默认 URL 规则。
- 某侧地址缺失或非法：该模式回退 `default`，不拼接、不补全、不修改原始地址。

桌面首页、移动首页、Spotlight 搜索结果、编辑态、访客页共用这一个选择结果；打开方式仍由原有 `bookmarkTarget` 决定。

## 2. 设计

### 2.1 选择类型

`web/src/network.ts` 新增：

```ts
type BookmarkAddressMode = 'lan' | 'wan' | 'default'

bookmarkAddressMode(
  preference: NetworkMode,          // 'auto' | 'lan' | 'wan'
  detected: AutoStatus | null,      // 'lan' | 'wan' | 'unknown' | null
  probing: boolean,
): BookmarkAddressMode
```

决策顺序：

1. `preference === 'lan' | 'wan'`：直接返回手动模式，不读取自动结果，探测中也不覆盖。
2. `preference === 'auto' && probing`：返回 `default`。
3. `preference === 'auto' && detected === 'lan'`：返回 `lan`。
4. `preference === 'auto' && detected === 'wan'`：返回 `wan`。
5. 其余（UNKNOWN、null）：返回 `default`。

`default` 是明确的“不做 LAN/WAN 选择”哨兵，不是第三种网络判断，也不会写入持久化。

### 2.2 URL 解析

`web/src/lib.ts`：

- `bookmarkHref(bookmark, mode = 'default')`
- `lan`/`wan` 模式优先读取对应字段的合法 HTTP(S) 地址。
- 对应字段缺失、空白或非法时调用 `defaultBookmarkHref`。
- `defaultBookmarkHref` 完全保留旧规则：合法 WAN 优先，其次合法 LAN；两端都不可用返回空字符串。
- 不拼接路径、不推导主机、不修改 `lan_url` / `wan_url` 原始值。

保留默认参数，使旧调用和旧测试无需改变行为。

### 2.3 组件接入

- `BookmarkCard.tsx` 增加 `addressMode` prop，默认 `default`；首页卡片仍只显示图标和名称，不显示 URL。
- `SpotlightSearch.tsx` 增加 `addressMode` prop；结果链接 href、鼠标点击、Enter 打开都使用同一 `bookmarkHref` 结果。
- `App.tsx` 在顶层计算一次 `bookmarkAddress = bookmarkAddressMode(networkMode, autoStatus, autoProbing)`，传给所有首页卡片与搜索；桌面和移动共用同一组件与规则。
- 顶部网络入口的 `aria-label` 增加“书签使用 LAN/WAN/默认地址”。
- `NetworkSheet.tsx` 增加状态条：“书签打开：LAN 地址 / WAN 地址 / 默认地址”，并说明地址缺失时沿用原有默认地址。
- `style.css` 增加 `.network-address-hint`，LAN 绿色、WAN 蓝色、default 灰色，兼容现有三套主题。

### 2.4 未改动的边界

- 未改 P4.1：网络模式仍只保存在当前浏览器，键名、默认值、持久化逻辑不变。
- 未改 P4.2：后端 HTTP 探测的接口、超时、状态码、结果语义不变。
- 未改 P4.3：浏览器自动判断的触发、缓存、超时、两轮判定、离线处理不变。
- 未使用 Ping、IP 子网推断、NAS 后端网络状态。
- 未改书签模型、导入导出格式、排序与布局。
- 未改权限控制；地址选择只在已通过权限过滤的书签列表上运行。
- 未改打开方式：`open_mode=self/current_tab` 仍为 `_self`，其余仍为 `_blank`。
- 未进入 P5，未增加 Docker 集成。

## 7. 已知限制

1. **UNKNOWN 的实际 URL 仍是旧默认地址。** 本批按任务书“UNKNOWN、判断中、地址缺失沿用现有默认 URL/打开行为”实现，旧默认规则是合法 WAN 优先。因此 UNKNOWN 时双地址书签仍会打开 WAN URL；但地址选择层返回 `default`，顶部与面板均显示“默认地址”，没有把 UNKNOWN 判定成 WAN。若产品希望 UNKNOWN 时完全不打开任何一侧，需要另行定义新的回退规则，不能在本批擅自引入。
2. **判断中不保留上一次结果。** 按任务书“判断中沿用现有默认行为”，探测一开始即从 LAN/WAN 切到 default；这是明确取舍，不是沿用旧结果。
3. **两端全空的书签无法由后端创建。** 浏览器缺失证据只能覆盖单侧缺失；两端全空由单元测试覆盖。
4. **测试地址均为 127.0.0.1 / 10.255.255.1 回环与不可达夹具**，不是真实路由器、NAS 或公网域名。
5. **ARM64 镜像与 QEMU 不在本批阻塞条件**；CI 仍会执行既有步骤，但本报告不以其作为验收前提。
6. 手动模式只在当前浏览器保存；换浏览器或清 localStorage 会回到 AUTO，这是 P4.1 既有语义，本批未改。
