## 1. 施工目标与边界

本批只解决一件事：**在用户当前浏览器中，判断当前页面所在浏览器是否处于 LAN 环境**。

- 判断必须由浏览器执行，不能使用 NAS 后端服务器的网络状态代替浏览器状态。
- 只使用 P4.1 已配置的主路由器、旁路由、NAS 三个固定目标，只探测已启用目标。
- 只使用 HTTP/HTTPS，不使用 Ping，不根据 IP 子网、网关或网段推断。
- 结果只归为 LAN、WAN、UNKNOWN。
- AUTO 下允许自动结果接管当前网络状态；手动 LAN/WAN 永远优先。
- 探测异步执行，不阻塞首页和书签加载。
- 未修改书签 LAN/WAN URL 最终选择逻辑，未开放任意 URL 探测，未进入 P4.4 或 P5。

## 2. 判断规范

### 2.1 浏览器执行与目标来源

浏览器通过新增的只读接口 `GET /api/network/targets` 获取执行探测所需的最小信息：

```json
{"targets":[{"key":"router","address":"127.0.0.1"}]}
```

- 只返回 `enabled=true` 且 `address` 非空的目标的 `key`、`address`。
- 不返回 `label`、`enabled`、`updated_at`、失败原因、后端探测结果、管理配置或错误堆栈。
- key 只能来自 P4.1 的三个固定目标；接口只读，`POST` 实测 404。
- 接口不接受 URL 参数，浏览器也不能把任意地址加入探测列表。

页面 HTTPS 时先试 HTTPS、再试 HTTP；页面 HTTP 时先试 HTTP、再试 HTTPS。IPv6 地址自动加方括号。目标 URL 只由已校验地址与 scheme 组成，固定为根路径 `/`，不携带路径或查询参数。

### 2.2 成功、失败与 UNKNOWN

浏览器探测使用 `fetch` 的 `no-cors` GET：

```
mode: 'no-cors'
credentials: 'omit'
cache: 'no-store'
referrerPolicy: 'no-referrer'
```

`no-cors` 返回 opaque 响应，无法读取 HTTP 状态码，也无法读取响应体。因此本批的“明确成功”定义为：**浏览器收到了目标返回的 HTTP/HTTPS 响应**，不要求 2xx。302 等重定向会被浏览器跟随，只要最终收到响应即视为可达。

- 任一启用目标明确成功：LAN。
- 第一轮全部明确失败：进入第二轮。
- 第二轮全部明确失败：WAN。
- `SecurityError` / `NotAllowedError`、HTTPS 页面到 HTTP 目标的 mixed content 预判、HTTPS 公网页面到私网目标可能被 PNA 拦截的 `TypeError`：UNKNOWN。
- 没有启用目标：UNKNOWN，且不发起目标请求。
- 浏览器离线：UNKNOWN，不探测。
- 无法读取目标接口：UNKNOWN。
- UNKNOWN 绝不转换为 LAN 或 WAN，也不覆盖手动模式。

单目标探测异常不会中断其他目标；所有目标并发执行，某目标异常只影响自己。

### 2.3 两轮与超时

| 阶段 | 单目标超时 | 行为 |
| --- | --- | --- |
| 第一轮 | 800ms | 任一成功立即 LAN，并 abort 其他目标 |
| 第二轮 | 500ms | 仅第一轮全部明确失败时执行；任一成功立即 LAN |
| 结束 | — | 两轮全部明确失败才 WAN；任一轮出现 UNKNOWN 直接保留 UNKNOWN |

成功即结束，不等待其他目标。第一轮出现 UNKNOWN 时不进入第二轮，避免把“不确定”误判成 WAN。每个目标独立计时；单目标的 HTTP/HTTPS 两次尝试共享该目标在本轮的截止时间。

### 2.4 AUTO 接管、触发与防重复

- AUTO 模式：自动判断结果可接管显示与当前网络状态。
- 手动 LAN/WAN：自动判断不覆盖；只有用户切回 AUTO 后才重新接管。
- 模式仍只保存在当前浏览器 `localStorage`，不写服务端、不跨浏览器/设备同步。
- 能触发判断的时机：
  - 页面打开 / mount；
  - 浏览器从后台回到前台（`visibilitychange`）；
  - `online` / `offline`；
  - Network Information `change`；
  - 用户在 AUTO 下手动点击“重新判断网络”；
  - 已有结果超过缓存有效期（60s）且页面在前台。
- 自动触发最小间隔 3s；单航班（in-flight）复用同一个 Promise；手动 `force` 可绕过最小间隔，但不能绕过正在执行的判断。
- 网络离线时直接 invalidate 为 UNKNOWN，并取消当前判断；恢复上线后重新判断。
- 探测在 `useEffect` 中异步执行，首页与书签渲染不等待探测完成。

## 9. 已知限制与未完成事项

1. **“成功”是收到 HTTP/HTTPS 响应，不是 HTTP 2xx**。`no-cors` 的 opaque 响应无法读取状态码和响应体；即使目标返回 404/500，只要浏览器收到了响应，本批也视为“明确可达”。这是浏览器跨域限制下的可达性判断，不是 P4.2 的 HTTP 健康判断。
2. **重定向会被跟随**。浏览器 `no-cors` 模式不能安全地配合 `redirect: 'manual'`（Chromium 会直接 TypeError），因此移除了该参数。目标若 302 到可访问地址，视为可达；P4.2 后端探测“不跟随重定向”的语义未受影响。
3. **HTTPS 部署且目标只有 HTTP 时，会稳定 UNKNOWN**。HTTPS 页面访问 HTTP 目标会被 mixed content 预判为不确定；若目标 HTTPS 又握手失败，最终仍是 UNKNOWN，无法据此判 WAN。这是安全策略下的取舍，不把“被浏览器拦住”当成 WAN。
4. **真实 CORS 不是本批实测对象**。产品探测刻意使用 `no-cors` 规避 CORS 预检；安全类异常（`SecurityError`/`NotAllowedError`、mixed content、HTTPS 公网页面到私网目标的 PNA 预判）归 UNKNOWN，但 Firefox/Safari 与真实公网 HTTPS 到私网 PNA 未做浏览器实测。
5. **无法通过正常后台制造“零启用目标”**。P4.1 保存接口强制至少一个启用目标；验收使用本地 `127.0.0.1:5444` 代理夹具覆写公开接口为 `{"targets":[]}`。产品代码在收到空列表时确实返回 UNKNOWN 且不发请求。
6. **验收目标均为本地回环夹具**。`127.0.0.1/.3/.4/.11/.12` 不是用户真实主路由、旁路由或 NAS；验证了真实浏览器 fetch、超时、连接拒绝、第二轮与 mixed content，但不覆盖真实设备证书、端口和响应策略差异。
7. **管理员截图使用测试会话注入**。`127.0.0.1:5180` 仅渲染生产 `dist` 并向 `/api` 注入隔离测试会话；产品代码没有登录绕过，测试口令未写入仓库、报告或截图。访客页面 `:5181` 不注入 Cookie。
8. **移动端为浏览器视口模拟**。390×844 验证了布局、无横向溢出与三主题，未在实体手机做触摸测试。
9. **手动重判截图有 250ms 人为延迟**。仅用于稳定截取“判断中”和禁用按钮；产品逻辑不包含该延迟。
10. **UNKNOWN 与不可区分异常**。除明确的安全异常外，普通 `TypeError` 仍可能来自 DNS、连接拒绝、TLS 失败等真实网络失败，代码按“明确失败”处理；只有安全页面到私网目标等可识别场景归 UNKNOWN。这是当前浏览器 API 的能力边界。
11. **未做定时后台探测**。自动判断只在上述用户态时机触发，不做后台周期任务；任务书未要求。
12. **未修改书签 URL 选择**。自动结果只驱动顶部状态与网络面板；书签 LAN/WAN URL 的最终选择逻辑保持不变，后续批次才处理。
