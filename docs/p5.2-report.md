# P5.2 实施报告 — Docker 容器自动发现与状态展示

日期：2026-11-28
状态：功能与 AMD64/Compose 验证完成，等待项目负责人验收
范围：仅实现容器自动发现、四态映射、只读列表、刷新与故障恢复；未实现任何 Docker 写操作、日志/终端入口或书签绑定，未进入 P5.3。

## 1. 交付摘要

P5.2 已完成以下内容：

- 通过 P5.1 已建立的 `docker-socket-proxy` 只读连接，请求 `GET /containers/json?all=1` 获取真实容器。
- 读取容器 ID、名称、镜像、状态、创建时间、启动时间、端口映射和 Labels；运行中与已停止容器均可发现。
- 统一映射 `running`、`stopped`、`error`、`unknown` 四态，并严格区分“Docker 连接失败”与“容器已停止”。
- “服务”面板新增容器统计、容器列表、手动刷新、自动刷新、加载中、空列表、连接失败和旧数据过期提示。
- 容器列表支持桌面、移动端与 AUTO/LIGHT/DARK 三主题；大量容器时列表内部滚动。
- 刷新失败保留上一次有效容器数据，并显示“当前显示上次有效数据”；Docker 恢复后下一次刷新自动恢复真实状态。
- 所有请求继续经 Socket Proxy，仅管理员可访问；未新增任何写接口，未直接挂载 Docker Socket。

## 2. 后端实现

### 2.1 容器读取

新增 `internal/dockerclient/containers.go`：

- `ListContainers(ctx)` 请求 `GET /containers/json?all=1`，使用 P5.1 同一个只读 HTTP 客户端。
- 只解析发现所需字段：`Id`、`Names`、`Image`、`Created`、`State`、`Status`、`Ports`、`Labels`。
- 输出脱敏 DTO：`id`、`name`、`image`、`status`、`created_at`、`started_at`、`ports`、`labels`。
- 不返回环境变量、容器配置、挂载详情或上游错误响应体。
- 上限 2000 个容器；单个容器 JSON 异常跳过并计入 `skipped`，不影响整个列表；超过上限标记 `truncated`。
- 对前 100 个容器并发（4）请求 `/containers/<id>/json` 补充 `State.StartedAt`；详情失败仅留空启动时间，不改变列表状态。

### 2.2 状态映射

映射逻辑在 `normalizeContainerStatus`，不使用 Docker 原始 `Status` 文本直接展示为最终状态：

| 统一状态 | 识别条件 | 颜色 |
|---|---|---|
| `running` | `State=running` 且 `Status` 不含 `unhealthy` | 绿色 `#16A34A` |
| `stopped` | `State=exited` 或 `State=created` | 灰色 `#9CA3AF` |
| `error` | `State=restarting`、`dead`、`paused`、`removing`，或 `running` 但状态文本含 `unhealthy` | 红色 `#DC2626` |
| `unknown` | 空状态、无法解析或未知状态 | 深灰 `#6B7280` |

连接失败时返回空容器列表，不把任何容器误报为 `stopped`；`counts.stopped=0`。Docker 数据尚未取得时前端显示“正在检测”与加载骨架，而不是四态中的某一态。

### 2.3 API

新增 `GET /api/admin/docker/containers`：

- 继续由现有 `requireAdmin` 保护，访客返回 401。
- 始终 HTTP 200 返回状态对象；上游失败不抛 5xx。
- 响应包含 `status`、`checked_at`、`message`、`read_only`、`refresh_interval_seconds`、`containers`、`counts`，可选 `skipped`、`truncated`。
- `status` 复用 P5.1 六态连接状态；容器 DTO 中只出现 P5.2 四态。
- 不向前端暴露 Proxy 地址、Socket 路径、内部错误堆栈或环境变量。

## 3. 前端实现

`DockerSheet.tsx` 保留 P5.1 连接状态卡，并新增：

- 容器统计条：总数、运行、停止、异常；存在未知时追加“未知”。
- 手动刷新按钮，刷新中禁用并显示“刷新中…”。
- 容器列表：名称、状态色点与文案、镜像、12 位短 ID、端口、创建/运行时间、标签数量。
- 空列表、加载中、连接失败、旧数据过期四种独立提示。
- API 版本、最近检测时间、自动刷新间隔。
- `inFlight` 防止重复请求；自动刷新期间不显示全屏加载。
- Labels 仅作为普通文本数据统计/展示，不拼接 HTML，不执行其中内容。

刷新失败处理：

- 若本次返回 `status != connected` 且已有有效列表，保留旧列表与旧统计，状态卡切换为“连接失败”，并显示“当前显示上次有效数据”。
- 若首次加载即失败，不展示虚构容器，显示连接失败空状态。
- Docker 恢复后，下一次手动或定时刷新会重新获取真实列表并清除 stale 标记。

表格宽度修正：三列改为 `minmax(0, …)`，桌面面板不再出现横向滚动条；移动端维持两列布局与列表内部纵向滚动。

## 4. 刷新与故障恢复

- 进入 Docker 页面立即请求一次。
- 自动刷新间隔由 `LOCALHUB_DOCKER_REFRESH_INTERVAL` 控制，默认 `30s`，允许 `10s–300s`；Compose 与 `.env.example` 已提供配置入口。
- 前端将间隔限制在 10–300 秒，避免高频轮询。
- 刷新请求串行化：`inFlight` 为真时直接返回，避免请求堆积。
- Docker 故障时 LocalHub 首页、书签、健康检查不受影响；容器 API 返回 `connection_failed` 与空列表。
- Docker 恢复后容器 API 恢复 `connected`，前端可再次发现 `p52-running`。

## 5. 安全与权限

- LocalHub 仍只访问 `docker-socket-proxy:2375`，不挂载 `/var/run/docker.sock`。
- 本批没有新增容器启动、停止、重启、删除、创建接口，也没有镜像、网络、卷、exec 或日志接口。
- 容器 API 仅管理员可访问；访客 401。
- Proxy allowlist 未修改，V-02 只读边界保持 15 PASS / 0 FAIL。
- 容器 Labels 作为不可信普通数据处理，不作为指令、HTML 或模板执行。
- 单个容器解析失败被跳过，不影响整个列表。

## 8. 已知限制

1. 本机执行环境没有 Docker CLI/容器权限，无法在本机创建真实容器；真实 Docker 发现由 GitHub Actions 宿主 Docker 完成，本地 UI 截图使用 CI 真实响应的字段投影回放。报告中已明确区分，未把回放截图当作本机实时发现。
2. 真实 CI 环境只创建了 `running` 与 `stopped` 两种 fixture；`error` 与 `unknown` 由单元测试覆盖，没有用模拟容器伪造真实页面。
3. 容器启动时间只对前 100 个容器补充详情，更多容器仅展示创建时间；这是有意的 API 负载限制。
4. Docker 容器列表最多 2000 个；超过时标记 `truncated`，不继续加载。
5. 本批未做书签与容器绑定，未修改书签数据模型、首页 UI 或 LAN/WAN 选择逻辑。
